# 아키텍처

## 목표

아이폰의 내비·음악 앱을 테슬라 중앙 화면에서 **보고, 터치로 조작하고, 소리를 듣는 것**.

## 왜 이 구조인가

| 방법                                                          | 결과                                                                                                              |
| ------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| 아이폰 앱만으로 화면 미러링 (ReplayKit)                       | 화면은 보낼 수 있지만, iOS는 다른 앱에 터치를 주입할 수 없어 **조작 불가**. 백그라운드 메모리 제한(50MB)도 빡빡함 |
| CarPlay 프로토콜 직접 구현                                    | Apple MFi 인증 칩이 필요해서 **불가**                                                                             |
| **시판 CarPlay 동글 + Raspberry Pi + 테슬라 브라우저** (채택) | 동글이 MFi 인증을 처리. CarPlay는 원래 차량 터치를 받도록 만들어져 있어 **조작 가능**                             |

테슬라에서 외부 화면을 띄울 수 있는 유일한 통로는 내장 브라우저이므로, Pi가 웹 서버가 되어 화면을 중계합니다.

## 구성 요소

```
┌──────────┐  무선 CarPlay   ┌──────────────┐  USB   ┌───────────────────────────────┐  Wi-Fi  ┌────────────────────────┐
│  iPhone  │ ─(BT + Wi-Fi)─▶ │ CarPlay 동글  │ ─────▶ │ Raspberry Pi                  │ ──────▶ │ 테슬라 브라우저          │
│          │ ◀────────────── │ (Carlinkit)  │ ◀───── │  server/                      │ ◀────── │  web/                  │
└──────────┘                 └──────────────┘        │  ├ CarlinkitDongle (node-carplay)│        │  ├ VideoRenderer       │
                                                     │  ├ HTTPS 정적 서버 + WebSocket │         │  │  WebCodecs → canvas  │
                                                     │  └ hostapd AP / dnsmasq       │         │  ├ TouchInput          │
                                                     └───────────────────────────────┘         │  └ AudioPlayer         │
                                                                                               └────────────────────────┘
```

| 코드                                   | 역할                                                                                                     |
| -------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| `server/src/dongle/DongleSource.ts`    | 화면/소리 공급원 인터페이스 (`video`, `audio`, `status`, `media` 이벤트, `sendTouch`, `requestKeyframe`) |
| `server/src/dongle/CarlinkitDongle.ts` | 실제 동글. node-carplay를 감싸 위 인터페이스로 변환                                                      |
| `server/src/dongle/MockDongle.ts`      | 개발용. `.h264` 파일을 프레임 단위로 반복 재생                                                           |
| `server/src/index.ts`                  | HTTPS(또는 HTTP) + WebSocket 서버, 뷰어별 키프레임 동기화와 백프레셔 처리                                |
| `shared/src/protocol.ts`               | 바이너리/JSON 메시지 규격 ([protocol.md](protocol.md))                                                   |
| `shared/src/h264.ts`                   | NAL 분할, 키프레임 판별, WebCodecs codec 문자열 생성                                                     |
| `web/src/VideoRenderer.ts`             | H.264 → `VideoDecoder` → `<canvas>`                                                                      |
| `web/src/TouchInput.ts`                | 포인터 이벤트 → 영상 기준 0..1 좌표 (레터박스 보정)                                                      |
| `web/src/AudioPlayer.ts`               | PCM → WebAudio 재생                                                                                      |

## 데이터 흐름

**영상** — 아이폰이 CarPlay UI를 H.264로 인코딩 → 동글 → USB → Pi가 프레임마다 6바이트 헤더를 붙여 WebSocket으로 전송 →
브라우저가 `VideoDecoder`로 디코딩해 canvas에 그림. 새 뷰어가 붙거나 디코더가 깨지면 Pi가 동글에 키프레임(`frame` 명령)을 요청하고,
그 뷰어에게는 다음 키프레임부터 보냅니다. 브라우저가 못 따라와 WebSocket 버퍼가 2MB를 넘으면 프레임을 버리고 다음 키프레임부터 다시 보냅니다.

**터치** — 브라우저 `pointerdown/move/up` → 영상 영역 기준 0..1 좌표 → JSON 메시지 → Pi → 동글(`SendTouch`, 0..10000 정수로 변환) → 아이폰.
CarPlay 동글은 단일 터치만 받으므로 첫 번째 손가락만 추적합니다(핀치 줌 불가, 지도는 CarPlay의 +/- 버튼 사용).

**오디오** — 동글이 PCM(44.1kHz 스테레오 등)을 보내면 Pi가 그대로 전달하고, 브라우저가 WebAudio로 재생합니다.

## 핵심 설계 결정

### 1. `<video>`가 아니라 WebCodecs + canvas

테슬라 브라우저는 주행 중 동영상 재생을 막습니다. 같은 문제를 겪은 Tesla Android 프로젝트 등은 canvas에 직접 그리는 방식으로 우회합니다.
WebCodecs는 하드웨어 디코딩을 쓰면서 지연이 가장 낮고, 별도 디코더 라이브러리가 필요 없습니다.
→ **실차 확인 필요**: 현재 펌웨어에서 주행 중 canvas 갱신이 유지되는지.

### 2. HTTPS 필수

WebCodecs는 보안 컨텍스트(HTTPS 또는 localhost)에서만 동작합니다. 테슬라 브라우저에서 Pi로 접속하려면 신뢰할 수 있는 인증서가 필요합니다
([network.md](network.md#https-인증서)).

### 3. 로컬 Wi-Fi 직결

테슬라 ↔ Pi는 Pi가 만든 Wi-Fi AP로 직접 연결합니다. 영상이 인터넷을 거치지 않으므로 지연이 낮고 셀룰러 데이터를 쓰지 않습니다.
아이폰 ↔ 동글도 동글 자체 Wi-Fi로 직결되므로, 아이폰의 셀룰러 인터넷은 그대로 CarPlay 앱(지도, 스트리밍)에 쓰입니다.

### 4. 오디오 경로는 두 가지를 열어 둠

- **기본: WebAudio** — 추가 설정 없음. 브라우저 정책상 첫 터치 후에만 소리가 납니다.
- **대안: Pi → 차량 블루투스(A2DP)** — 브라우저 오디오가 주행 중 막히거나 지연이 크면, Pi를 블루투스 오디오 소스로 테슬라에 연결합니다(BlueALSA 등).
  → **실차 확인 후 결정**.

### 5. 동글 드라이버는 의존성으로

동글 USB 프로토콜은 node-carplay(MIT)가 이미 역공학해 두었습니다. 네이티브 `usb` 모듈이 필요하므로 optionalDependency로 두고 실행 시 불러와,
동글이 없는 개발 PC에서도 목업으로 개발할 수 있게 했습니다.

## 한계

- **CarPlay를 지원하는 앱만** 됩니다. YouTube(동영상), 일반 웹 브라우저 등은 CarPlay 앱이 아니어서 표시되지 않습니다.
- 단일 터치만 지원(동글 제약).
- 영상 지연은 아이폰 인코딩 + 동글 + Wi-Fi + 디코딩을 합쳐 대략 100~200ms 수준이 목표입니다(실측 전).
- Siri/통화 마이크: node-carplay는 Pi에 연결된 마이크를 사용합니다. 마이크 경로는 로드맵 4단계에서 다룹니다.
- 테슬라 펌웨어 업데이트로 브라우저 정책이 바뀔 수 있습니다.
